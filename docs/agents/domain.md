# Domain documentation

This is a single-context repository.

When domain terms or architectural decisions are changed:

- use CONTEXT.md at the repository root if it exists;
- use docs/adr/ for architectural decision records;
- create these files lazily when a real term or decision needs to be recorded;
- do not create empty domain files merely to satisfy configuration.

Use the vocabulary already established in CONTEXT.md. Surface conflicts instead of silently replacing an existing term.
